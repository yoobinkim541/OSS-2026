# 2026-09-25 — GUI에서 RViz 3D 재생 바로 열기

## 문제
- **증상:** GUI의 "RViz 궤적 저장"은 JSON을 저장하고 WSL에서 칠 명령만 알려 줬습니다. 3D로 보려면 WSL 터미널을 열어 `bash sim/run_rviz.sh ...`를 직접 실행해야 했습니다.
- **추가 문제:** `run_rviz.sh`는 RViz 창을 닫아도 재생 스크립트(`--loop`)가 계속 돌았습니다. 다시 실행하면 RViz와 노드가 중복으로 떴습니다.

## 해결
- **GUI 버튼:** "RViz 3D로 보기"로 바꿨습니다. 동작 순서는 다음과 같습니다.
  1. 시뮬레이션을 아직 안 했으면 먼저 실행합니다.
  2. 관절 궤적을 `out/rviz_traj.json`(설치판은 사용자 출력 폴더)에 저장합니다.
  3. WSL에서 `run_rviz.sh`를 창 없이 백그라운드로 실행하고, RViz 창은 WSLg로 뜹니다.
  - 버튼은 처리 결과가 생기면 바로 켜집니다.
- **`mirobot_sketch/rviz_launch.py` (새 모듈)**
  - `wsl -l -q` 출력(UTF-16LE)에서 배포판 목록을 읽습니다. docker-desktop은 제외하고, 22.04를 먼저 봅니다.
  - `/opt/ros/humble`과 `~/mirobot_ws`가 있는 배포판을 찾아 기억합니다. 이 PC에서는 `Ubuntu-22.04`를 1.4초 만에 찾았습니다. 환경 변수 `MIROBOT_WSL_DISTRO`로 직접 지정할 수도 있습니다.
  - 경로를 `/mnt/c/...`로 바꾸고, 공백이 있으면 따옴표로 감쌉니다. 실행 로그는 `rviz_launch.log`에 남깁니다.
  - ROS가 없는 PC에서는 설치 조건을 안내하고 실행하지 않습니다.
- **`sim/run_rviz.sh`**
  - 시작할 때 이전 `rviz_playback.py`, `rviz2`, `robot_state_publisher`를 정리합니다.
  - 재생을 백그라운드로 돌리고 `wait $RVIZ`로 기다리므로, RViz 창을 닫으면 모두 종료됩니다.
- **중복 제거:** 궤적 문서를 만드는 코드가 GUI와 CLI(`--export`)에 따로 있던 것을 `mirobot_sim.trajectory_doc()`로 합쳤습니다.
- **설치판(exe):** `sim/run_rviz.sh`, `rviz_playback.py`, `rviz/mirobot_sketch.rviz`를 PyInstaller 데이터에 넣었습니다.

## 확인
- **실제 실행(이 PC, Ubuntu-22.04 + Humble)**
  - F 시험 궤적을 실행하니 rviz2, robot_state_publisher, rviz_playback이 모두 떴습니다.
  - 다시 실행하면 rviz2와 재생 프로세스가 각각 1개만 남았습니다.
  - rviz2를 종료하면 관련 프로세스가 0개가 됐습니다.
- **GUI 코드 경로:** 앱 생성 → illust1 처리 → `view_rviz()`를 실행하니 시뮬레이션 PASS 후 RViz에서 7,837개 샘플을 20배속으로 재생했습니다. 오류 대화상자는 없었습니다.
- **자동 테스트:** `tests/test_rviz_launch.py`를 추가했습니다(전체 75개 통과). WSL 호출은 가짜로 대체해 CI의 Ubuntu에서도 돕니다.
  - 경로 변환, 배포판 탐지, ROS가 없을 때의 안내, 실행 명령 구성, 스크립트 포함 여부와 LF 줄바꿈, 궤적 형식을 확인합니다.
  - 패키지 전체 컴파일 검사도 넣었습니다. 작업 중 GUI 문자열의 줄바꿈 실수를 테스트가 잡지 못했기 때문입니다. GUI 모듈은 테스트에서 import하지 않습니다.

## 한계
- RViz는 앱 안에 포함되지 않고 별도 창(WSLg)으로 뜹니다.
- WSL2 + ROS 2 Humble + mirobot_ws가 설치된 PC에서만 동작합니다. 다른 PC에서는 기존 "로봇 시뮬레이션"(관절 여유 검사)만 됩니다.
