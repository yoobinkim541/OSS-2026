# GUI에서 로봇으로 그리기 + RViz 실시간 따라가기

설계 문서 · 2026-09-26

## 1. 배경과 목표

- **지금 상태**
  - 실제 드로잉은 명령줄 실행기(`mirobot draw … --execute`)로만 할 수 있습니다.
  - GUI의 [RViz 3D로 보기]는 시뮬레이션 궤적을 20배속으로 반복 재생할 뿐, 실제 로봇 진행과 관계가 없습니다.
- **목표:** **GUI에서 로봇으로 그리기를 시작하고, 로봇이 그리는 동안 RViz의 로봇팔과 펜 자국이 실물과 같은 위치를 따라가게** 합니다. 진행률과 남은 시간도 보여 줍니다. 로봇이 없어도 **가상 시뮬레이션**으로 전체 흐름을 시험할 수 있어야 합니다.

### 사용자가 정한 것
- **목적:** 실물과 나란히 보여 주기(발표·시연, 진행 확인)
- **실행 위치:** GUI에 [로봇으로 그리기] 버튼을 둡니다. 명령줄과 같은 안전 절차를 거칩니다.
- **위치 추적 방식:** A안. 명령 응답(`ok`) 기준으로 따라가고, 응답 사이는 예상 속도로 보간합니다. 실제 좌표 읽기(B안)는 로봇을 연결한 뒤 선택 기능으로 붙일 자리만 둡니다.
- **실행 창:** 단계 표시줄(①~⑥)로 지금 단계, 할 일, 멈춘 이유를 보여 줍니다.
- **이름:** 로봇 없이 시험하는 모드는 "가상 시뮬레이션"이라고 부릅니다.

### 성공 기준
- 가상 시뮬레이션 20배속으로 GUI에서 시작하면 다음이 확인돼야 합니다.
  - 단계 표시가 ①→⑥으로 진행합니다.
  - 진행 막대와 RViz 로봇·펜 자국이 같은 명령 위치를 따라갑니다. 보간은 다음 명령의 끝을 넘지 않습니다.
- [멈춤]이나 오류가 나면 다음 명령을 보내지 않고, RViz도 그 자리에 섭니다. 결과와 보낸 명령 수가 실행 기록에 남습니다.
- 명령줄 실행기의 동작과 기존 테스트는 바뀌지 않습니다.
- 에이전트 도구에는 로봇 실행 기능이 없습니다(변화 없음).

## 2. 안전 절차와 실행 흐름

```
① 사전 검사 → ② 연결·호밍 → ③ 시작 위치 확인 → ④ 최종 확인 → ⑤ 그리는 중 → ⑥ 끝
   (①~④에서 문제가 있으면 "시작하지 않음": 포트를 닫고 이유를 보여 줌)
```

| 단계 | 누가 | 내용 | 실패하면 |
|---|---|---|---|
| ① 사전 검사 | 자동 | 결과 있음. 실행기 허용 범위 안(넓은 범위는 체크했을 때만 허용). 로봇 시뮬레이션 PASS/WARN(없으면 먼저 실행, FAIL이면 거부) | 이유와 해결 방법 |
| ② 연결·호밍 | 사람 | 포트 열기(보드 리셋) → "가운데 버튼 2초" 안내 → Idle까지 대기, [취소] 가능 | 시간 초과·취소 |
| ③ 시작 위치 | 자동 | 현재 TCP와 종이 중심 설정의 거리가 `max_start_offset_mm` 이하인지 | 벗어난 거리 표시 |
| ④ 최종 확인 | 사람 | 요약(획·명령·예상 시간·크기·포트), 연결 선택(로봇 / 가상 시뮬레이션+배속), 공중 모드(기본 켬), 넓은 범위, **"종이·펜·주변 확인" 체크를 해야 [시작]이 켜짐** | [취소] |
| ⑤ 그리는 중 | 자동 | 명령 전송·`ok` 대기. `ok`마다 진행 콜백 호출. [멈춤]을 누르면 다음 명령부터 보내지 않음 | 오류 응답·시간 초과 → ⑥ 오류 |
| ⑥ 끝 | — | 결과(완료 / 사용자 멈춤 / 오류와 실패한 명령), `runs/run-*.json` 기록, 포트 닫기 | — |

- **자동 복구는 하지 않습니다**(명령줄과 같은 원칙). 멈춤이나 오류 뒤에는 펜과 로봇 상태를 확인하라고 안내합니다.
- **닫기 확인:** 그리는 중에 창을 닫거나 앱을 끄려고 하면 "멈추고 닫을까요?"를 묻고, 멈춘 뒤 포트를 닫습니다.
- **단계 목록은 한 곳에서:** 실행기 코드의 목록 하나(`DRAW_STEPS`: id·이름·누가)에서 GUI 표시줄과 명령줄 출력이 같은 이름을 씁니다.

## 3. 진행 파일과 RViz 따라가기

```
GUI 실행 스레드 ──(ok마다)──► <출력 폴더>/live_progress.json ◄──(0.05초마다 읽기)── WSL: rviz_playback.py --follow
```

- **진행 파일:** 같은 폴더에 임시 파일로 쓴 뒤 `os.replace`로 바꿔 넣어, 반쯤 쓴 파일을 읽지 않게 합니다.
  ```json
  {"run_id": "20260926-153012", "state": "homing|running|stopped|done|error",
   "acked": 1234, "total": 4209, "t": 1790387781.2, "speed": 1.0, "tcp_mm": null,
   "trajectory": "<궤적 JSON 경로>", "message": "…"}
  ```
  - `tcp_mm`은 B안(실제 좌표 읽기)을 붙일 자리입니다. 값이 있으면 따라가기가 그 좌표를 우선합니다(이번 범위에서는 항상 `null`).
- **궤적:** `mirobot_sim.trajectory_doc`이 점마다 `cmd`(그 점이 속한 G-code 명령 번호, 0부터)를 넣습니다. 시작 자세 점은 `cmd = -1`입니다.
- **위치 계산 (`live_progress.follow_index`, 순수 함수):**
  - 입력: 궤적 점 목록, `acked`, 마지막 응답 시각, 현재 시각, 배속, 펜다운·이동 속도
  - 출력: 지금 보여 줄 점 번호
  - 규칙:
    - `acked`개 명령이 끝난 점까지는 확정입니다.
    - 그 뒤로는 (현재 시각 − 마지막 응답 시각) × 속도 × 배속만큼 1mm 간격 점을 앞으로 가되, 다음 명령(`acked`번)의 끝 점을 넘지 않습니다.
    - `state`가 `stopped`, `error`, `done`이면 확정 위치에서 멈춥니다.
- **`rviz_playback.py --follow <진행 파일>`**
  - 타이머마다 파일을 읽어 `follow_index`로 위치를 정하고, `/joint_states`와 펜 자국을 발행합니다. 펜 자국은 지나온 펜다운 구간까지만 그립니다.
  - 상태 글자(텍스트 마커)를 종이 위에 띄웁니다: "그리는 중 29%", "멈춤", "오류: …", "완료".
  - `run_id`가 바뀌면 궤적을 다시 읽고 펜 자국을 지웁니다.
- **`rviz_launch.launch(traj, follow=<진행 파일>)`:** 따라가기 모드로 실행합니다. 이미 떠 있는 창은 지금처럼 정리합니다.
- **RViz 없는 PC:** WSL이나 ROS가 없으면 RViz 버튼만 흐리게 하고 이유를 보여 줍니다. 드로잉은 그대로 할 수 있습니다.

## 4. 가상 시뮬레이션

- **`VirtualMirobotLink` (`virtual_robot.py`):** `MirobotLink`와 같은 메서드(`wait_for_homing`, `query_status`, `send_and_ack`, `wait_idle`, `close`)를 가집니다.
  - **호밍:** 짧은 대기 뒤 `Idle`과 종이 중심 TCP를 돌려줍니다.
  - **`send_and_ack`:** G-code의 XYZ와 F를 해석해, 직전 위치와의 거리 ÷ 속도 + `assumed_command_latency_s`만큼 (÷배속) 기다린 뒤 돌아옵니다. 시간 계산은 `estimate_time`과 같은 가정을 씁니다.
  - **오류 흉내:**
    - `fail_at=N`: N번째 명령에서 Alarm 오류
    - `timeout_at=N`: 응답 없음
    - `start_offset_mm`: 시작 위치를 어긋나게 함
    - `homing_fails`: 호밍 실패
  - **`should_stop` 확인:** 기다리는 도중에도 짧은 간격으로 멈춤을 확인해, 배속이 낮아도 [멈춤]이 바로 듣습니다.
- **선택:**
  - GUI ④에서 "가상 시뮬레이션 (로봇 없이)"을 고르고 배속을 1×, 5×, 20×, 50× 중에서 정합니다. 설정 파일의 포트가 없으면 이것만 고를 수 있습니다.
  - 명령줄에서는 `mirobot draw <json> --execute --virtual [--virtual-speed 20]`입니다.
- **기록:** 실행 기록에 `"virtual": true`와 배속을 남깁니다.

## 5. GUI

- **버튼:** "③ 실행" 카드에 **[로봇으로 그리기]**를 둡니다. 누르면 실행 창(`CTkToplevel`)이 뜹니다. 실행하는 동안 메인 창의 조절 칸, 편집, 에이전트 도구 실행은 잠깁니다.
- **실행 창 구성**
  - **단계 표시줄:** ✓ 지난 단계, ● 지금 단계, ✕ 문제가 생긴 단계, ○ 남은 단계
  - **"지금 할 일" 한 줄**
  - **단계별 내용:**
    - ④에서는 요약, 연결 선택, 체크박스, [취소]·[시작]
    - ⑤에서는 진행 막대(명령 a/b, %), 획 i/n, 경과·남은 시간, [RViz 3D로 따라보기], [■ 멈춤]
    - ⑥에서는 결과, 실행 기록 경로, [RViz로 다시 보기], [닫기]
- **남은 시간:** 남은 명령의 예상 시간 합계에 실제 경과/예상 비율을 곱해 보정합니다.
- **메인 창:** 요약 카드의 "예상 시간"에 진행률을 함께 보여 줍니다. 편집 단계 그림에서는 이미 그린 획을 진하게 표시합니다.
- **스레드:** 실행은 작업 스레드에서 합니다. 화면 갱신은 기존 `app.ui()` 큐로만 합니다.

## 7. 테스트와 확인

- **실행기 단계:**
  - 가상 시뮬레이션으로 ①→⑥ 순서와 콜백 호출 횟수(명령 수와 같음)를 확인합니다.
  - 실패 경우:
    - 범위 초과나 시뮬레이션 FAIL → ①
    - 시작 위치 어긋남 → ③
    - `fail_at` → ⑤ 오류(보낸 명령 수, 실패한 명령)
    - 멈춤 → "사용자 멈춤"
  - 명령줄 호환: 기존 `test_draw_executor`가 통과하고, `--virtual` 명령줄 경로도 확인합니다.
- **진행 파일:** 쓰는 도중에 읽어도 깨진 JSON이 나오지 않는지(여러 스레드로 반복 쓰기·읽기) 확인합니다.
- **`follow_index`:**
  - `acked`까지는 확정인지
  - 보간이 다음 명령의 끝을 넘지 않는지
  - 배속을 반영하는지
  - 멈춤이나 오류에서 고정되는지
  - 시작 자세 점을 제대로 처리하는지
- **궤적:** `cmd`가 0부터 차례로 늘고, 명령마다 점이 1개 이상 있는지 확인합니다.
- **GUI 스모크 (가상 시뮬레이션 50배속):**
  - 체크를 하지 않으면 [시작]이 꺼져 있는지
  - 시작 후 단계 표시와 진행 막대가 움직이는지
  - [멈춤]이 동작하는지
  - 실행 중에 편집이 잠기는지
  - 끝나면 실행 기록 파일이 생기는지
- **직접 확인:**
  - 가상 시뮬레이션 20배속으로 GUI 실행 → RViz 프로세스, 진행 파일, 펜 자국이 진행률과 맞는지 봅니다.
  - 멈추면 RViz가 그 자리에 서는지 봅니다.
  - 화면 캡처는 사용자가 PC를 쓰지 않을 때만 합니다.

## 8. 범위 밖과 이후

- B안(`?` 상태 조회로 실제 좌표 읽기)은 로봇을 연결한 뒤, 진행 파일의 `tcp_mm` 칸을 채우는 방식으로 붙입니다.
- 실물 절차: 공중 모드 → 실제 드로잉 순서로 시험하고, 화면이 실물보다 앞서는 정도를 재서 보정 값(`display_lag_s`)을 정합니다.
- 더 큰 그림(비대칭 허용 범위·아래로 옮긴 배치)은 별도 설계로 다룹니다.
