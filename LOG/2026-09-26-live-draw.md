# 2026-09-26 — GUI에서 로봇으로 그리기 + RViz 실시간 따라가기

설계: `docs/superpowers/specs/2026-09-26-live-draw-rviz-follow-design.md`
계획: `docs/superpowers/plans/2026-09-26-live-draw-rviz-follow.md`
브랜치: `feature/live-draw`

## 문제
- 실제 드로잉은 명령줄 실행기로만 할 수 있었습니다.
- RViz는 시뮬레이션 궤적을 반복 재생할 뿐, 로봇이 지금 어디를 그리는지와 상관이 없었습니다.
- 로봇 없이 전체 흐름을 시험할 방법이 없었습니다.

## 해결
- **실행기 단계 함수** (`draw_executor.py`)
  - 사전 검사(`preflight`), 연결·호밍(`connect_and_home`, 취소 가능), 시작 위치(`check_start`), 기록(`write_run_record`)을 함수로 나눴습니다.
  - 단계 이름은 한 곳(`DRAW_STEPS`: ①사전 검사 ②연결·호밍 ③시작 위치 확인 ④최종 확인 ⑤그리는 중 ⑥끝)에 둡니다.
  - `execute()`에 `on_ack`(ok마다 알림)와 `should_stop`(멈춤)을 추가했습니다.
  - 명령줄은 출력과 반환 코드를 그대로 유지하고, `--virtual`, `--virtual-speed`를 추가했습니다.
- **가상 시뮬레이션** (`virtual_robot.py`)
  - 호밍, 명령마다 (거리 ÷ 속도 + 명령 지연) ÷ 배속만큼 기다린 뒤 ok, 오류·시간 초과·시작 위치 어긋남 흉내를 제공합니다.
  - 기다리는 중에도 멈춤을 0.02초 간격으로 확인합니다.
- **`DrawJob`** (`draw_job.py`)
  - ①~⑥을 작업 스레드에서 진행하고, ④에서 사람이 확인할 때까지 기다립니다.
  - 멈춤이나 취소가 들어와도 포트는 항상 닫습니다. 자동 복구는 하지 않습니다.
  - 실행 기록에 `"virtual": true`와 배속을 남깁니다.
- **진행 파일** (`live_progress.py`)
  - 임시 파일에 쓴 뒤 `os.replace`로 바꿔 넣고, Windows에서 잠깐 잠기면 다시 시도합니다.
  - 따라가기 위치(`FollowTrack`)는 ok를 받은 명령까지를 확정하고, 그 뒤는 예상 속도로 보간하되 다음 명령의 끝을 넘지 않습니다.
- **궤적:** 점마다 G-code 명령 번호(`cmd`)와 명령별 속도(`cmd_feed_mm_min`)를 넣었습니다.
- **RViz 따라가기:** `rviz_playback.py --follow <진행 파일>`로 실행합니다.
  - 종이 위 상태 글자(drawing N% / stopped / done / error)를 띄우고, 지나온 펜다운 구간만 자국으로 그립니다.
  - 상태 글자는 WSL RViz에 한글 글꼴이 없을 수 있어 영어로 했습니다.
  - 설치판(exe)에도 `sim/mirobot_sketch/live_progress.py`를 넣었습니다.
- **GUI 실행 창** (`draw_window.py`)
  - 단계 표시줄(✓ ● ✕ ○)과 "지금 할 일"을 보여 줍니다.
  - 연결 방식: 로봇 / 가상 시뮬레이션 + 배속(1×, 5×, 20×, 50×, 500×)
  - 옵션: 공중 모드(기본 켬), 넓은 범위 허용
  - "종이·펜·주변 확인" 체크를 해야 [시작]이 켜집니다.
  - 그리는 중에는 진행 막대, 남은 시간, [RViz 3D로 따라보기], [■ 멈춤]을 보여 줍니다.
  - 그리는 동안 조절 칸, 재계산, 편집 적용, 에이전트의 편집 도구를 잠급니다(읽기 도구는 허용).
  - 앱이나 창을 닫으면 먼저 묻고, 멈춘 뒤 닫습니다.

## 진행 중 발견해 고친 것
- **기본 크기 그림이 사전 검사에서 거부됨:** 앞선 리뷰 반영 때 종이 배치를 고정하면서, 세션이 반올림된 배율·중심(소수 6자리·3자리)으로 mm를 계산했습니다. 그래서 가장자리 점이 50.000096mm가 돼 기본 100mm 그림이 "범위 초과"로 막혔습니다. 종이 배치에 반올림하지 않은 변환값(`transform`)을 따로 넣어 해결했습니다.
- **RViz를 여는 동안 드로잉이 10초 밀림:** 이 PC에서 확인하니 WSL이 깨어나는 동안 [시작] 뒤 약 10초 동안 명령이 하나도 나가지 않았습니다. RViz 실행을 별도 스레드로 옮겼습니다. RViz는 진행 파일로 현재 위치를 따라잡습니다.
- **"넓은 범위 허용"이 사전 검사에 반영되지 않음:** ① 사전 검사부터 적용되게 고쳤습니다.

## 최종 리뷰 반영
리뷰(새 컨텍스트)에서 Critical은 0건, Important는 3건이었습니다. Minor 중 2건은 효과를 다시 따져 Important로 올렸습니다. 모두 재현 테스트를 먼저 쓰고 고쳤습니다.
1. **①~④ 동안 잠금 없음:** 호밍 중 편집이나 이미지 열기로 로봇이 그리는 그림과 화면·RViz·기록이 달라질 수 있었습니다.
   - [연결 시작]부터 잠급니다. 이미지 열기와 메인 창 RViz 버튼도 잠급니다.
   - ①에서 획·시뮬레이션·경로·설정을 **한 번에 찍어 두고**(스냅숏), 궤적과 기록을 그것으로 만듭니다.
2. **닫기 대기가 짧음:** 실제 로봇은 응답 대기가 최대 15초인데 닫기는 10초만 기다려서, 포트를 쥔 스레드가 남은 채 잠금만 풀릴 수 있었습니다.
   - 응답 대기 시간 + 5초를 기다리고, 그래도 안 끝나면 창과 잠금을 유지한 채 알립니다.
   - 시작하는 순간 상태를 '진행 중'으로 둡니다.
   - 포트 닫기가 실패해도 끝 이벤트를 보내 잠금이 풀리게 합니다.
3. **진행 파일 쓰기가 드로잉을 멈출 수 있음:** 백신 등이 임시 파일을 잠그면 실제 드로잉이 오류로 끝날 수 있었습니다.
   - 진행 파일 쓰기는 이제 절대 예외를 내지 않습니다(재시도한 뒤 `last_error`에 기록).
   - 계속 실패하면 짧게만 시도해 드로잉을 늦추지 않습니다.
4. **그리는 중 메인 RViz 버튼:** 누르면 따라가기 화면이 꺼졌습니다. 그리는 중에는 잠급니다.
5. **끝난 뒤 버튼 상태:** 끝나면 [시작]과 확인 체크를 끕니다. RViz를 못 연 이유는 끝난 뒤에도 기록 경로와 함께 남깁니다.

## 확인
- **자동 테스트:** 173개 통과, pyflakes 깨끗. 새 테스트 파일은 다음과 같습니다.
  - `test_live_progress`: 원자적 쓰기, 교체 재시도, 따라가기 위치
  - `test_virtual_robot`: 시간, 오류, 1배속에서 멈춤 0.9초 안
  - `test_draw_job`: 단계 순서, 확인 전 대기, 멈춤, 취소, RViz 없음, 느린 RViz
  - `test_draw_executor`: 단계 함수와 명령줄 `--virtual`
  - GUI 스모크: 실행 창 전체 흐름, 앱 종료 시 안전하게 멈춤
- **명령줄:** `mirobot draw orientation-test-F.json --execute --virtual`로 11개 명령이 완료되고 기록이 남았습니다.
- **GUI + 실제 RViz (이 PC, illust1, 가상 50배속)**
  - 명령 4,209개, 예상 25.6분인 그림입니다.
  - [시작] 1초 뒤 명령 93개가 나가고, 이후 초당 약 70개로 진행했습니다.
  - WSL에서 `rviz2`와 `rviz_playback.py --follow`가 실행 중이었고, `/sketch_markers`에 종이·펜·자국·상태 글자 마커가 발행됐습니다.
  - [멈춤] → 명령 1,548개에서 멈추고, 진행 파일 `stopped`, 잠금 해제, 실행 기록(`virtual: true`) 저장까지 확인했습니다. 확인에 쓴 가상 실행 기록은 지웠습니다.
  - 사용자가 PC를 쓰는 중이라 화면 캡처는 하지 않았습니다.

## 로봇을 연결한 뒤 할 일
1. 공중 모드로 F 시험 경로를 실행해 RViz와 실물의 움직임이 맞는지 봅니다.
2. 실제 드로잉을 하면서 화면이 실물보다 앞서는 정도를 재고, 필요하면 보정 값(`display_lag_s`)을 정합니다. 컨트롤러가 명령을 버퍼에 받아 두면 ok가 이동 완료보다 먼저 올 수 있습니다.
3. 차이가 크면 B안(`?` 상태 조회로 실제 좌표 읽기)을 붙여 진행 파일의 `tcp_mm` 칸을 채웁니다.
