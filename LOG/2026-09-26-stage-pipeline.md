# 2026-09-26 — 단계별 선 추출 파이프라인과 편집 제안

설계: `docs/superpowers/specs/2026-09-26-stage-pipeline-edit-proposals-design.md`
계획: `docs/superpowers/plans/2026-09-26-stage-pipeline-edit-proposals.md`
브랜치: `feature/stage-pipeline`

## 문제
- **중간 결과가 안 보임:** 선 추출이 `run_pipeline()` 한 덩어리라 어느 단계에서 선이 빠지거나 지저분해졌는지 볼 수 없었습니다.
- **다시 계산이 느리고 수동:** 값을 바꾸면 "처리 실행"으로 처음부터 다시 계산해야 했습니다.
- **밝기가 비슷한 색의 경계가 사라짐:** 흑백 변환 때문에 주황 배경과 머리카락처럼 밝기가 비슷한 두 색의 경계가 없어졌습니다.
- **버린 선을 되살릴 수 없음:** 파이프라인이 버린 선(작은 덩어리, 잔가지, 겹침)을 다시 살릴 방법이 없었습니다.
- **편집 수단이 부족:** 편집은 삭제와 되돌리기뿐이었고, 설정을 다시 처리하면 사라졌습니다. 사람이 "이 선"을 가리킬 번호도 없었습니다.

## 해결
- **`stages.py`**
  - 단계 7개를 `ParamSpec`(범위·기본값·설명)과 계산·미리보기 함수로 정의했습니다.
  - `Pipeline`은 `(앞 단계 키, 단계, 설정)` 해시로 단계별 결과를 캐시하고, 바뀐 첫 단계부터만 다시 계산합니다.
  - 기존 `run_pipeline()`은 이 파이프라인을 부르는 얇은 함수가 됐습니다.
- **Lab 선 검출:** `compute_edges_lab()`는 L·a·b 채널별 Canny를 합칩니다. a·b 채널은 대비를 2배로 늘립니다.
- **버린 조각 기록:** `trace_strokes`와 `dedupe_strokes`가 버린 조각을 이유(small, spur, overlap)와 함께 기록합니다. 기본 결과는 그대로입니다.
- **세션**
  - 설정이 바뀔 때마다 세대 번호를 올리고, 오래된 계산은 버립니다(`StaleRun`).
  - 번호표: 획 1..N, 추가한 획, 후보 순으로 번호를 매깁니다.
  - 편집 흐름은 제안(`propose_edits`) → 적용(`apply_proposals`, exclude/only) → 되돌리기입니다.
  - 편집은 모양으로 기록합니다. 다시 계산하면 지운 모양과 60% 이상 겹치는 획을 다시 지웁니다.
- **배경 제거 캐시:** 배경 제거 결과를 컬러로 캐시해서, 배경을 지운 상태에서도 색 차이 검출을 쓸 수 있습니다.
- **GUI**
  - 단계 띠(썸네일 9개), 큰 보기(휠 확대·끌어 이동·원본 겹치기), 단계별 조절 칸(자동 생성)을 만들었습니다.
  - 값을 바꾸면 0.3초 뒤 자동으로 다시 계산합니다.
  - 편집 단계는 벡터로 그립니다. 번호는 보이는 획에만 최대 400개까지 붙이고, 버린 선은 점선으로, 제안은 빨강·초록으로 표시합니다.
  - 제안 바에서 번호 딱지를 눌러 뺀 뒤 적용할 수 있습니다.
- **에이전트 도구**
  - `set_params` 스키마를 단계 정의에서 만듭니다.
  - `view`로 단계별 결과, 편집 화면(원본 겹치기·후보), 확대 보기를 볼 수 있습니다.
  - `list_strokes`, `get_stroke`, `propose_edits`(10종), `apply_proposals`, `discard_proposals`를 추가했습니다.
  - 예전 `delete_strokes`/`delete_region`은 `propose_edits`로 합쳤습니다.

## 진행 중 발견해 고친 것
- **투명 PNG에서 획이 사라짐:** 흑백으로 읽을 때 투명 부분이 검게 돼 선이 묻혔습니다. 이제 알파가 있는 이미지만 흰 배경에 합성합니다. JPG 결과는 그대로라 기준값이 같습니다.
- **빈 옵션 프레임:** CTkFrame의 기본 높이가 200px이라 큰 보기 위에 빈 공간이 생겼습니다(화면 캡처에서 발견).
- **`main thread is not in main loop` 경고:** 단계를 바꿀 때 버린 조절 칸의 tk 변수를 작업 스레드의 가비지 컬렉션이 정리하면서 났습니다. 조절 칸을 버린 직후 메인 스레드에서 `gc.collect()`로 정리합니다.
- **이모지:** Tk 글꼴이 🟢🔴를 빗금 원으로 그려서 색 이름으로 바꿨습니다.

## 최종 리뷰에서 나온 문제와 수정
리뷰어(새 컨텍스트)가 브랜치 전체를 검토했습니다. Critical은 0건, Important는 7건이었고 모두 재현 테스트(`ReviewFixesTest`, GUI 스모크)를 먼저 쓴 뒤 고쳤습니다.

1. **다시 계산이 실패하면 결과가 반쯤 남음:** 예를 들어 획이 0개가 되면, 시간·종이 미리보기가 없는 결과가 남아 상태 조회와 내보내기가 `KeyError`로 실패했습니다. 이제 계산 전 상태를 스냅숏으로 저장해 두고 실패하면 되돌립니다.
2. **적용이 원자적이지 않음, NaN 좌표 허용:** 적용 중 실패하면 번호표와 되돌리기 기록이 반쯤 바뀌었습니다. 적용과 되돌리기도 스냅숏으로 되돌리고, 유한하지 않은 좌표는 거부합니다.
3. **느슨한 입력 검사:** `ids: "12"`가 1번과 2번 삭제로 해석됐고, `3.7`이나 `true`도 번호로 받아들였습니다. 이제 정수와 목록만 받고, 좌표는 `[x, y]` 숫자 두 개만 받습니다.
4. **mm 좌표가 움직임:** 편집을 적용할 때마다 종이 배치를 새 테두리 상자에 다시 맞춰서, 모든 획의 mm 좌표가 바뀌었습니다. 이제 종이 배치는 선 추출 결과를 기준으로 고정하고, 다시 계산하거나 크기를 바꿀 때만 새로 정합니다. 편집 뒤 그림 크기는 실제 획으로 다시 잽니다.
5. **배경 제거 캐시가 섞임:** 배경 제거(약 1분) 도중 다른 이미지를 열면, 이전 이미지 결과가 새 이미지 캐시에 들어갈 수 있었습니다. 이제 캐시 키를 `(경로, rembg)`로 하고, 시작 시점의 캐시에만 씁니다.
6. **제안 수천 개에서 GUI가 느려짐:** 3,000건이면 다시 그리는 데 15.5초가 걸렸습니다. 이제 제안을 색마다 `LineCollection` 하나로 그리고, 번호 딱지는 보이는 범위에서 제안 먼저 최대 400개까지만 붙입니다. 테스트는 5초 안에 끝나는지와 딱지 수를 확인합니다.
7. **적용 규칙:** 빈 선택으로 적용해도 제안이 전부 사라지고 빈 되돌리기 기록이 남았습니다. 이제 다음처럼 동작합니다.
   - 빈 선택이면 거부합니다.
   - 고르지 않은(뺀) 제안은 확인 전 제안으로 남습니다.
   - 확인 전 제안이 있는 번호는 `apply_now`로 바로 적용하지 않고 오류로 알립니다.

## 확인
- **리팩터링 전후 결과 비교:** 전에 저장한 기준값(합성 16건, 샘플 6장 × 2가지 = 12건)과 결과가 **모두 같습니다**(`tests/test_golden.py`).
- **자동 테스트:** 전체 123개가 통과하고 pyflakes도 깨끗합니다. 새로 만든 테스트 파일은 다음과 같습니다.
  - `test_stages.py`: 단계 정의, 캐시, 오래된 계산 버리기, 미리보기, Lab
  - `test_edits.py`: 점 편집, 모양 재적용, 초록/빨강 렌더링
  - `test_agent.py`의 `EditSessionTest`: 제안·적용·빼기·묶음, 범위 밖 좌표, 전부 삭제 거부, 다시 계산 뒤 유지, 목록 자르기
  - `test_gui_smoke.py`: 창을 띄워 값 변경 → 자동 재계산, 제안 바 적용
- **속도** (`python tests/golden.py --perf`, 이 PC):

| 이미지 | 전체 계산 | 단순화만 바꿨을 때 | 획 수 (밝기 / 색 차이) |
|---|---|---|---|
| illust1 | 0.94 s (첫 실행은 skimage 로딩 포함 3.3 s) | 0.004 s | 296 / 357 |
| illust2 | 0.89 s | 0.006 s | 485 / 472 |
| illust3 (만화) | 1.65 s | 0.011 s | 878 / 823 |
| photo1 | 0.56 s | 0.004 s | 285 / 383 |
| photo2 | 0.65 s | 0.004 s | 370 / 435 |
| photo3 | 0.55 s | 0.003 s | 304 / 327 |

  목표(전체 2.5초 이하, 뒤 단계만 0.3초 이하)를 앱을 켠 뒤 첫 계산을 빼고는 모두 만족합니다. 색 차이 방식은 일러스트와 사진에서 획이 8~34% 늘어납니다. 흑백에서 사라지던 색 경계가 잡히기 때문입니다.
- **화면:** 라이트/다크 모드에서 선 검출·뼈대 단계(원본 겹치기)와 편집 단계를 캡처해 직접 확인했습니다. 편집 단계에서는 제안 4건, 딱지 하나 빼기, 확대 시 번호를 확인했습니다.
