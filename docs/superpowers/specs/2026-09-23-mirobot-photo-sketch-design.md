# 사진 기반 스케치 생성 및 Mirobot 드로잉 프로젝트

설계 문서 · 2026-09-23

## 1. 프로젝트 개요

오픈소스프로그래밍 수업의 텀프로젝트로, 입력한 사진을 단순하고 그릴 수 있는 선 경로로 변환한 뒤 WLKATA Mirobot 로봇팔이 펜으로 종이에 그리는 시스템을 만든다. 전체 작업 기간은 약 8주로 잡는다.

프로젝트의 핵심은 컴퓨터 비전(OpenCV)을 이용해 사진에서 선을 추출하고 정리하는 과정과, 로봇팔이 그 선을 실제 종이 위에 그리는 과정을 하나의 실행 가능한 파이프라인으로 연결하는 것이다. 사용자가 상세도 수준을 바꾸면 선의 양과 예상 그리기 시간이 달라지도록 해 CV와 로보틱스의 결합을 시연한다.

## 2. 현재 확정된 조건

### 개발 환경과 제어 구조

- WSL2 Ubuntu 22.04에 ROS 2 Humble과 MoveIt 2를 설치했다.
- WSL2에서는 Mirobot 모델 확인, RViz 시각화, MoveIt 기반 경로 계획을 수행한다.
- USB 패스스루된 CH340 포트는 WSL2에서 명령을 쓸 수 있지만 응답을 읽지 못한다. 같은 포트를 Windows 네이티브 pyserial로 열면 응답이 정상 확인됐다.
- 따라서 첫 버전은 실시간 ROS 2 하드웨어 브리지를 만들지 않는다. WSL2에서 계산한 관절 궤적을 파일로 내보내고, Windows Python 실행기가 그 파일을 읽어 pyserial로 재생하는 구조를 사용한다.
- WLKATA 공식 ROS 2 저장소를 빌드할 때 누락된 textures 폴더와 .setup_assistant 파일을 보충해야 했으며, 현재 작업 환경에서는 이를 보완해 빌드에 성공했다. 이후 재현을 위해 이 보충 내용을 설치 안내에 기록한다.

### Mirobot 실측 동작

- 전원을 켜면 로봇 상태가 Alarm으로 시작한다. 중앙 네비게이션 버튼을 약 2초 눌러 수동 호밍을 시작하고 Home을 거쳐 Idle이 될 때까지 약 15~30초 기다린다.
- 새 시리얼 연결을 열 때 CH340이 컨트롤러를 리셋한다. 실행 중에는 연결을 한 번만 열고 계속 재사용한다.
- 관절 이동은 다음 G-code 형식을 사용한다.

  M21 G90 G00 X{j1} Y{j2} Z{j3} A{j4} B{j5} C{j6}

- 상태 조회는 ? 명령을 보내고 응답의 상태 필드를 읽는다. 상태가 Idle인지 확인한 뒤 다음 동작을 보낸다.
- 그리퍼와 펌프는 같은 M3 S 명령을 사용하지만 장착한 장치에 따라 값의 의미와 범위가 다르다. 펜 드로잉 첫 버전에서는 그리퍼와 펌프를 제어하지 않는다.
- 펜 홀더를 장착하고 종이를 벽에 수직으로 고정했다. 펜이 종이에 닿는 정도는 일반적인 Cartesian Z 좌표로 정하지 않는다. 실제 구성에서는 팔의 전진·후진에 해당하는 관절 자세가 접촉 여부를 결정한다.
- 펜이 종이에 닿는 pen-down 자세와 살짝 떨어지는 pen-up 자세는 아직 보정 중이며, 관절값을 1~2도씩 조정해 찾는다.

## 3. 목표와 범위

### 이번 프로젝트의 목표

1. 사진을 입력해 로봇이 그릴 수 있는 선 경로를 만든다.
2. 선의 상세도를 조절할 수 있게 한다. 낮은 상세도에서는 작은 윤곽과 불필요한 점을 줄여 그리는 시간과 이동량을 줄인다.
3. 픽셀 경로를 벽에 고정한 종이의 좌표로 변환한다.
4. WSL2 MoveIt 2에서 로봇의 관절 경로를 계획하고 시각화한다.
5. Windows 실행기가 계획된 경로를 안전하게 Mirobot에 순차 전송해 펜으로 스케치한다.
6. 여러 이미지와 상세도 설정을 사용해 결과물, 경로 크기, 그리기 시간을 비교한다.

### 첫 버전에서 다루지 않을 항목

- 카메라 기반 실시간 추적과 자동 재시도
- 딥러닝 기반 의미 분할이나 생성형 이미지 변환
- 로봇팔의 펜 압력 자동 제어
- 3차원 표면이나 이동하는 물체에 대한 드로잉
- Windows와 WSL2 사이의 실시간 양방향 ROS 2 통신

핵심 파이프라인이 안정된 뒤에만 웹캠 기반 확인과 제한된 자동 복구를 2단계 확장으로 추가한다. 1단계 완료 기준은 카메라나 언어 모델 없이도 사진에서 경로를 만들고 안전하게 종이에 재생하는 것이다.

## 4. 사용자 흐름과 전체 데이터 흐름

1. 사용자가 사진 파일과 상세도 수준을 선택한다.
2. CV 모듈이 이미지를 흑백·대비 보정하고 Canny 엣지를 계산한다.
3. findContours로 윤곽 후보를 만들고, 너무 작은 윤곽을 제거한 뒤 approxPolyDP로 점 개수를 줄인다.
4. 정리된 선 경로와 원본 이미지를 겹친 미리보기를 보여준다. 사용자는 결과를 확인하고 상세도를 조정한다.
5. 경로 점들을 이미지 좌표에서 종이 위의 2차원 작업 평면 좌표로 변환한다. 별도 위치 지정이 없으면 도형의 경계 상자 중심을 종이 정중앙에 맞춘다.
6. WSL2의 MoveIt 2가 각 경로 점에 대해 역기구학과 관절 경로를 계산하고 RViz에서 검토한다.
7. 계획 결과를 여섯 관절의 각도와 pen-up/pen-down 동작이 담긴 JSON 궤적 파일로 저장한다. 관절 순서는 로봇의 X/Y/Z/A/B/C 축과 이름으로 명시해 순서 혼동을 막는다.
8. Windows 실행기가 궤적 파일을 읽는다. COM 포트를 한 번 열고 로봇 상태가 Idle인지 확인한 다음 관절 이동 명령을 순차 전송한다.
9. 각 스트로크 시작 전에는 pen-up으로 이동하고, 선의 시작점에서 pen-down한 뒤 경로를 따라 이동한다. 스트로크가 끝나면 pen-up으로 들어 다음 선으로 이동한다.
10. 실행 결과를 종이 사진으로 기록하고, 입력 미리보기 및 계획 경로와 비교한다.

### 2단계 확장 데이터 흐름: 카메라 피드백

1. 종이와 로봇 작업 영역을 고정 웹캠으로 촬영한다. 종이 모서리 또는 기준 마커를 이용해 영상에서 종이 좌표계를 찾고 원근을 보정한다.
2. OpenCV가 계획된 경로와 실제 종이의 잉크 선을 비교해 누락, 끊김, 위치 오차를 측정한다. 웹캠 분석은 매 프레임의 로봇 제어가 아니라 스트로크 전후 확인과 오류 발생 시점의 캡처에 사용한다.
3. 로컬 비전 언어 모델은 캡처 이미지와 컨트롤러 로그를 받아 실패 원인 후보와 신뢰도를 구조화된 결과로 반환한다. 모델은 관절각이나 G-code를 직접 실행하지 않는다.
4. Windows 안전 감독기가 컨트롤러 상태, MoveIt 경로 한계, OpenCV 측정값, 모델의 분류 결과를 함께 검사해 재시도·재계획·정지 중 하나를 결정한다.
5. 모든 시도에서 이미지, 계획 경로, 관절 상태, 원인 분류, 조치를 저장해 결과를 재현하고 발표 자료로 활용한다.

## 5. 주요 구성요소

### 5.1 이미지 처리 및 경로 생성

입력 이미지에 흑백 변환과 대비 조절을 적용한 후 Canny 엣지 검출과 findContours로 선 후보를 만든다. 윤곽 길이 또는 크기 기준으로 작은 조각을 필터링하고 approxPolyDP로 경로를 단순화한다.

상세도 설정은 Canny 임계값, 최소 윤곽 길이, approxPolyDP의 epsilon을 묶어 조정한다. 추가로 경로 점 수, 펜이 종이에 닿아 움직이는 총 거리, pen-up 이동 거리를 계산한다. 여러 선의 순서는 가능한 한 가까운 끝점부터 이어 이동 거리를 줄인다.

Canny는 사진의 질감이나 그림자도 엣지로 잡을 수 있고, 물체 경계에 두 줄을 만들 수 있다. 따라서 작은 윤곽 필터와 상세도 조절을 핵심으로 검증한다. 결과가 복잡한 사진에서 계속 지저분하면 선 정리 또는 스켈레톤화 같은 고전 CV 단계를 확장 후보로 평가한다. 첫 구현부터 딥러닝에 의존하지 않는다.

### 5.2 종이 좌표 보정

종이를 벽에 평평하게 고정하고 네 모서리에 대응하는 로봇 평면 좌표를 기록한다. 네 쌍의 점으로 픽셀 좌표에서 로봇 작업 평면으로 가는 선형 아핀 변환을 계산하고, 보정에 쓰지 않은 내부 지점이나 종이 중앙에서 오차를 확인한다. 입력 이미지의 가로세로 비율은 유지하면서 종이의 안전 여백 안에 맞춘다.

종이가 휘거나 움직이면 보정값이 달라지므로, 종이를 고정한 뒤 보정하고 드로잉 중에는 위치를 바꾸지 않는다. 카메라로 비스듬히 촬영된 입력 사진의 원근 보정은 핵심 요구사항이 아니며 필요할 때만 별도 이미지 전처리로 추가한다.

도형 배치의 기준점은 펜의 현재 위치가 아니라 종이 중심이다. 생성 경로의 경계 상자 중심을 작업 평면 원점에 맞추고, 가로세로 비율을 유지하며 안전 여백 안에 배치한다. 원은 원의 중심, 하트와 사진 스케치는 경로 경계 상자의 중심을 종이 정중앙에 맞춘다. 사용자가 별도의 위치나 크기를 정하면 그 설정을 우선한다.

### 5.3 pen-up과 pen-down

접촉 자세가 아직 미확정이므로 첫 하드웨어 작업으로 수행한다. 펜과 종이에 무리가 가지 않는 범위에서 작은 관절 변화부터 시험하고, 종이에 닿아 선이 그어지는 값과 펜이 확실히 떨어지는 값을 기록한다. 두 자세를 pen_down()과 pen_up() 헬퍼로 제공한다.

그 뒤 짧은 수평선, 수직선, 대각선과 사각형을 반복해서 그려 펜 접촉과 종이 좌표 변환을 함께 확인한다. 일반적인 로봇 Z축을 펜 압력값으로 가정하지 않는다.

종이 중앙에 펜이 놓여 있어도 중앙점이 도형의 시작점이라고 가정하지 않는다. pen-up이 보정된 뒤에는 중앙에서 도형의 시작점으로 이동하고, 시작점에서 pen-down한 후 전체 윤곽을 그려 닫힌 경로를 완성한다. 원과 하트 모두 도형 중심이 종이 중심과 일치해야 하며, 하트 꼭짓점을 종이 중심에 두지 않는다.

### 5.4 MoveIt 경로 계획과 Windows 실행기

MoveIt 2는 경로의 관절 해를 만들고 RViz에서 범위와 움직임을 검토하는 역할을 한다. 실물 컨트롤러는 Windows pyserial 실행기만 연다. 초기 버전은 복잡한 네트워크 브리지 대신 공유 파일을 사용해 두 환경을 분리한다.

JSON 궤적에는 형식 버전, 단위, 관절 이름과 각도, 펜 상태 및 명령 순서를 기록한다. MoveIt의 관절 순서와 Mirobot의 X/Y/Z/A/B/C 축 대응을 명시적으로 매핑하고, 라디안과 도 단위 변환을 한 곳에서 처리한다. 실행 전에는 축 부호와 영점이 실제 관절 움직임과 일치하는지 작은 동작으로 검증한다.

Windows 실행기는 COM 포트를 한 번 열고 유지한다. 자동 호밍은 수행하지 않는다. 사용자가 물리 버튼으로 호밍을 완료한 뒤 상태가 Idle인 것을 확인해야 실행한다. 각 관절 명령 후 완료 상태를 확인하고 다음 명령으로 넘어가며, 오류나 예상하지 못한 상태에서는 실행을 중단한다.

### 5.5 웹캠 상태 확인과 실패 복구(2단계 확장)

웹캠은 종이와 펜 끝, 그려진 선을 볼 수 있도록 고정한다. 종이 네 모서리나 기준 마커로 카메라 영상을 종이 좌표계에 맞춘 뒤, OpenCV가 실행 전후 이미지에서 실제 선의 위치와 연속성을 측정한다. 노출·그림자·펜 색상에 민감하므로 조명을 고정하고 빈 종이 기준 영상을 저장한다. 결과 판정 임계값은 실제 펜과 종이로 실험해 정한다.

로컬 비전 언어 모델은 OpenCV가 확신하지 못하거나 실패를 검출했을 때만 캡처와 로그를 분석한다. Qwen3-VL은 이미지 및 영상 입력을 지원하는 후보 모델이며, RTX 5080의 16GB VRAM에서 작은 모델과 양자화 설정부터 추론 시간·메모리를 측정한다. 특정 모델 크기는 실측 후 정한다. [Qwen3-VL 공식 저장소](https://github.com/QwenLM/Qwen3-VL), [NVIDIA RTX 5080 사양](https://www.nvidia.com/en-us/geforce/graphics-cards/50-series/rtx-5080/)

Codex는 저장된 캡처·상태 로그를 바탕으로 개발 중 문제 분석과 결과 요약을 돕는 선택적 도구로 둔다. 실시간 제어 경로에는 넣지 않는다. 낮은 지연과 반복 가능한 제어가 필요한 스트로크 재생 및 정지는 Windows 안전 감독기와 일반 코드가 담당한다.

자동 재시도는 무한 반복이 아니라 실패 유형별로 제한한다. 초기 정책은 스트로크당 자동 재시도 최대 2회로 두고, 매번 원인을 바꿔 조치한 뒤 웹캠으로 다시 검증한다.

- 선이 누락되거나 끊겼으면 펜 접촉이 이미 보정된 허용 범위 안에서만 접촉값을 조정하고 해당 스트로크를 다시 시도한다.
- 선 전체가 어긋났으면 종이 기준 마커가 안정적으로 검출되는 경우에 한해 좌표 보정을 다시 계산한다.
- MoveIt/컨트롤러 소프트 리밋, Alarm, 시리얼 오류, 작업 영역 침범, 사람의 손이나 장애물 감지, 낮은 시각 신뢰도는 자동 재시도하지 않고 정지 및 사용자 확인 대상으로 처리한다.
- 물리 비상정지와 컨트롤러 상태 감시는 카메라나 언어 모델 판단을 대체하지 않는다.

성공 판정은 컨트롤러가 정상 Idle 상태이고, 계획 경로와 실제 잉크 선의 겹침·연속성이 실험으로 정한 기준을 통과하는 경우로 정의한다. 카메라가 종이 모서리나 잉크를 확실히 판별하지 못하면 성공으로 간주하지 않고 사용자 확인을 요청한다.

## 6. 8주 작업 계획

| 기간 | 작업 | 완료 기준 |
|---|---|---|
| 1주차 | 펜 접촉 자세를 조금씩 탐색하고 pen-up/pen-down 값을 기록한다. Windows 시리얼 연결을 한 번만 열어 쓰는 동작도 재확인한다. | 수동 호밍 후 펜업·펜다운을 반복할 수 있고, 같은 값으로 비슷한 접촉이 재현된다. |
| 2주차 | 펜 헬퍼를 만들고 저속으로 선, 대각선, 사각형을 그린다. 관절 이동 한계와 종이 안전 영역을 기록한다. | 펜이 종이를 긁거나 종이 밖으로 나가지 않고 기본 도형을 그린다. |
| 3주차 | 종이 네 모서리의 로봇 좌표를 측정하고 픽셀-작업 평면 변환을 구현한다. 내부 점으로 오차를 점검한다. | 알려진 이미지 좌표의 점과 선이 종이의 예상 위치에 그려진다. |
| 4주차 | Canny, findContours, 작은 윤곽 필터, approxPolyDP, 경로 미리보기를 구현한다. | 사진 한 장에서 미리보기 경로와 선 수·점 수·경로 길이를 출력한다. |
| 5주차 | MoveIt 2에서 이미지 경로의 작업 평면 점을 관절 경로로 변환하고 RViz에서 검사한다. JSON 궤적 형식을 확정한다. | 단순한 선과 도형의 계획 결과가 설정된 관절 범위 안에 있고 파일로 저장된다. |
| 6주차 | Windows 궤적 실행기를 구현하고 공유 파일을 통해 실제 로봇에 짧은 경로를 재생한다. | 연결을 유지한 채 펜업 이동과 펜다운 스트로크를 연속 실행한다. |
| 7주차 | 단순·중간·복잡한 사진으로 상세도 설정을 비교하고, 선 정리와 그리기 시간 문제를 보완한다. | 세 이미지의 미리보기와 실제 스케치, 경로 및 시간 측정값이 확보된다. |
| 8주차 | 반복 시연, 결과 정리, 발표 자료와 실패 시 사용할 간단한 도형 데모를 준비한다. 핵심 시연이 안정된 경우에만 웹캠 캡처·선 비교의 최소 기능을 시험한다. | 재현 가능한 핵심 실행 순서와 예비 데모가 준비된다. 시간이 허용되면 카메라 전후 캡처와 선 검증 결과를 추가한다. |

일정의 우선순위는 펜 보정과 실제 종이 좌표화, CV 경로 생성, 전체 통합 순이다. 앞 단계가 지연되면 이미지 처리의 확장보다 안정적인 선화 데모를 먼저 완성한다.

웹캠 피드백, 로컬 VLM, 자동 복구는 필수 8주 완료 기준이 아닌 확장 기능이다. 카메라 보정과 자동 복구 구현이 핵심 시연을 위협하면 캡처 후 수동 비교까지만 시연한다.

## 7. 검증과 프로젝트 성과 측정

### 기능 검증

- 물리 호밍 후 Idle 상태에서만 실행이 시작되는지 확인한다.
- 실행 중 USB 연결을 다시 열지 않고 전체 경로를 재생하는지 확인한다.
- RViz 미리보기, 내보낸 궤적, 실제 관절 움직임의 축 순서와 방향이 일치하는지 점검한다.
- 펜업 이동, 펜다운 선 긋기, 다음 스트로크 이동이 의도한 순서로 실행되는지 확인한다.
- 경로가 종이 영역과 설정된 관절 범위를 벗어나면 실행 전에 거부한다.
- 2단계 확장에서는 웹캠 종이 좌표 보정과 선 검출이 알려진 시험 경로를 허용 오차 안에서 찾는지 확인한다.
- 자동 복구는 누락 선, 좌표 오차, 컨트롤러 리밋처럼 실패 유형별로 허용된 조치만 수행하며, 제한 횟수 후에는 반드시 정지하는지 확인한다.
- 컨트롤러 오류·시리얼 단절·마커 불확실성에서 카메라 또는 VLM이 임의 관절 명령을 내리지 않는지 확인한다.

### CV 및 시연 평가

단순한 이미지, 보통 복잡도의 물체 사진, 세부 질감이 많은 사진을 테스트 세트로 사용한다. 각 이미지에 낮음·중간·높음 상세도를 적용해 다음 값을 기록한다.

- 추출된 스트로크 수와 전체 경로 점 수
- pen-down 총 길이와 pen-up 이동 거리
- 실제 그리기 시간과 실행 성공 여부
- 종이 결과물에서 주요 윤곽이 알아볼 수 있는지에 대한 시각 평가

핵심 결과는 상세도를 낮출 때 점과 이동량, 그리기 시간이 줄고 주요 윤곽은 유지되는지 보여주는 것이다. 경로 미리보기와 실제 스케치를 나란히 제시해 CV 출력과 로봇 동작을 함께 평가한다.

| 웹캠이 사람이나 손을 놓치거나 늦게 감지함 | 카메라 기반 감지는 보조 감시로만 사용하고, 컨트롤러 상태 확인과 사용자의 물리 비상정지를 유지한다. |

## 9. 최종 시연 구성

1. 입력 사진과 사용자가 선택한 상세도를 보여준다.
2. CV 미리보기와 추출된 스트로크 수·경로 길이를 제시한다.
3. RViz에서 계획된 팔 경로를 확인한다.
4. Windows 실행기에서 로봇 상태와 연결을 확인하고, 실제 종이에 펜으로 그린다.
5. 다른 상세도 설정 결과와 그리기 시간 차이를 비교한다.
6. 입력 이미지, CV 미리보기, 실제 스케치를 한 화면에 놓고 성과와 한계를 설명한다.
7. 선택적 확장 시연에서는 웹캠의 종이 보정 영상과 계획·실제 선 비교를 보여준다. 재시도 사례는 안전하게 복구 가능한 오류 하나를 사용하고, 리밋·통신 오류에서는 정지하는 동작도 함께 설명한다.

USB나 계획 문제가 생길 때를 위한 예비 시연으로는 미리 검증한 단순 도형 궤적 파일을 사용한다.

## 10. 현재 상태와 다음 작업

확인 완료: WSL2 Ubuntu 22.04, ROS 2 Humble, MoveIt 2 설치 및 로봇 모델 빌드; Windows pyserial 통신; 관절 명령과 상태 조회; 전원 켤 때 수동 호밍 필요; 시리얼 재연결 시 리셋.

실물 제어 추가 확인: Windows에서 관절 및 Cartesian 직선 경로 명령과 `?` 상태 응답을 확인했다. 100mm 원 경로는 48개의 직선 구간으로 실행해 Idle 복귀를 확인했다. 하트 시도는 19번째 구간에서 `Soft limit:B`로 중단했고, 이미 지난 경로를 역순으로 재생해 종이 중앙으로 복귀했다. 따라서 리밋 상태는 자동 재시도 대상이 아니라 경로 재계획 및 사용자 확인 대상으로 처리한다. 궤적 명령 수와 구간별 상태 대기가 실제 실행 시간을 크게 늘릴 수 있다는 점도 확인했다.

배치 요구사항: 종이는 A4 가로 방향이며, 사용자는 펜 끝을 종이 중앙에 위치시킨다. 이후 그리는 원·하트 등 도형은 도형 중심을 종이 정중앙에 맞춘다. 중앙 펜 위치를 도형의 꼭짓점이나 윤곽 시작점으로 취급하지 않는다.

진행 중: 벽면 종이 구성에서 펜업·펜다운 자세와 종이 좌표 보정. 웹캠과 자동 재시도는 아직 구현하지 않았으며 2단계 확장으로 계획한다.

바로 다음 작업: pen-up과 pen-down 자세를 안전하게 확정하고, 헬퍼로 고정한 뒤 짧은 기본 도형을 실제 종이에 그린다. 그 결과를 기준으로 종이 모서리 좌표 보정에 들어간다. 핵심 파이프라인이 안정된 뒤 고정 웹캠과 OpenCV의 전후 선 검증을 먼저 추가하고, 비전 언어 모델 진단과 제한 재시도는 그 다음에 평가한다.

## 11. OpenCV 학습 및 구현 방향 (2026-09-24)

- CV 1차 구현은 OpenCV 중심의 재현 가능한 파이프라인으로 시작한다. 기본 엣지 후보는 Canny/threshold이며, 선화 모드는 skeletonize와 stroke 추적을 별도 단계로 둔다.
- 학습 기반 모델은 기본 경로를 대체하지 않는다. PiDiNet은 Canny와 같은 입력 세트에서 비교하고, 복잡한 배경에서 대상 선택이 필요한 경우에만 SAM2를 별도 선택 단계로 평가한다. Qwen3-VL은 사진 설명/실행 후 관찰의 보조 역할로 제한한다.
- 구현 전 OpenCV 이미지 배열, BGR/회색조, blur/Canny, threshold/morphology, contour, skeletonize 순으로 학습한다.
- 첫 실습 자료와 실행 스크립트는 docs/opencv-study/lesson-01-image-basics.md 및 lesson-01.py에 있다. 연구 근거와 모델/저장소 비교는 LOG/2026-09-24-cv-model-research.md를 참고한다.

## 12. 구현 정리와 결정 갱신 (2026-09-24)

자세한 문제 정의와 검증 결과는 LOG/2026-09-24-cleanup-and-fixes.md에 있다.

- 원·하트 실행은 로봇 조작을 익히기 위한 수동 테스트였다. 실행 결과 값(중심 TCP, 펜업 후퇴 방향, ACK 응답, `Soft limit` 응답)은 robot/drawing_config.json의 초기값과 실행기의 오류 처리 근거로만 사용한다.
- **1차 실행 경로:** 컨트롤러의 Cartesian 직선 이동(`M20 G90 G01`)을 사용한다. 원·하트 테스트가 이 방식으로 끝까지 실행됐고, 관절 궤적 방식은 실물에서 검증된 적이 없기 때문이다. MoveIt 2는 RViz 경로 검토와 도달 범위 확인 용도로 유지한다. 관절 궤적 JSON 방식은 Cartesian 방식에서 도달·특이점 문제가 확인될 때 다시 평가한다.
- **CV 기본 경로:** Canny(사진) 또는 어두운 선 마스크(선화)를 만든 뒤, 골격화한 중심선을 한 번씩만 따라가는 획 추적을 기본으로 한다. findContours 방식은 1px 선을 왕복해 같은 선을 두 번 그리므로 비교용으로만 남긴다.
- **rembg 배경 제거:** 기본값을 끄고 선택 전처리로 둔다. 3절의 "딥러닝 기반 의미 분할" 제외 항목은 경로 생성의 핵심 단계를 뜻하며, 사용자가 켜는 전처리 옵션은 허용한다.
- **데이터 형식:** CV 출력은 종이 중심 기준 mm(x 오른쪽 +, y 위쪽 +)의 sketch_strokes JSON이다. 로봇 Y/Z 축의 부호와 중심 TCP 변환은 실행기 설정이 담당한다. 따라서 로봇 설정이 바뀌어도 CV 결과를 다시 만들 필요가 없다.
- **기본 그리기 크기:** 100 × 100 mm 상자 안(±50 mm)으로 제한한다. 끝까지 실행된 가장 큰 도형이 100 mm 원이기 때문이다.
