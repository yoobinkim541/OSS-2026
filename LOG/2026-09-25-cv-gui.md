로봇이 없는 동안 CV와 GUI를 먼저 다듬었습니다. 사용자가 고른 네 가지를 모두 진행했습니다: GUI 기능 보강, 획 이어붙이기, 이중선 줄이기, 시간 추정 개선. 로봇은 움직이지 않았습니다. 수치는 `input/`의 이미지 6장으로 측정했고, 이미지와 결과물은 git에 올리지 않습니다.

## 1. 획 이어붙이기 (`merge_strokes`)

**정의.** 골격 추적은 분기점마다 획을 나눕니다. 획마다 펜을 올렸다 내리기 때문에 획이 많을수록 시간이 늘어납니다. 그런데 끝점이 만나는 두 획을 이어 그려도 종이에 남는 결과는 같습니다.

**해결.**
- 획 끝점을 가까운 것끼리 묶어 노드로 만들고, 획을 노드 사이의 간선으로 보는 그래프를 만듭니다.
- 홀수 차수 노드부터 출발해, 쓰지 않은 간선을 따라 걸으며 한 획으로 잇습니다. 갈래가 여러 개면 진행 방향이 가장 덜 꺾이는 쪽을 고릅니다.

**검증.**
- 단위 테스트:
  - T자는 3획에서 2획이 됩니다(최소값).
  - "+"자는 가로 1획과 세로 1획으로 곧게 이어집니다.
  - 글자에서 그려지는 픽셀 차이가 1% 미만입니다.
- 실제 이미지(high 설정, 이어붙이는 거리 2px):

| 이미지 | 획 수 | 달라진 픽셀 |
|---|---|---|
| 일러스트 1 | 709 → 358 | 30 / 26,939 |
| 만화 | 320 → 208 | 37 / 19,798 |
| 사진 2 | 952 → 447 | 103 / 14,747 |

## 2. 이중선 줄이기 (`dedupe_strokes`)

**정의.** Canny는 굵은 선의 양쪽 경계를 각각 잡습니다. 그래서 한 선이 두 줄로 그려지고, 펜을 대고 긋는 길이와 시간도 두 배가 됩니다.

**시도 1 (실패): 엣지를 부풀린 뒤 골격화.**
가까운 두 경계를 하나의 띠로 합치려는 방법이었습니다. 반지름 2~4px로 시험했더니, 가까운 선들이 세포 모양의 그물로 뭉쳤습니다. 일러스트의 눈과 입이 망가져서 버렸습니다.

**시도 2 (채택): 이미 그린 선 근처의 중복 구간 제거.**
- 긴 획부터 따라가며, 지나간 곳 주위 dist_px를 "그린 영역"으로 표시합니다.
- 그린 영역 안에 들어가는 구간은 지우고, 밖의 구간만 남깁니다.
- 근거: 펜 굵기는 약 0.5mm이고, 800px 이미지를 100mm로 그리면 약 4px입니다. 이보다 가까운 두 선은 종이에서 구별되지 않습니다.

**구현 중 고친 점 두 가지.**
1. Canny 앞의 5px 블러 때문에, 2px 선도 양쪽 경계가 4px 떨어져 잡혔습니다(측정: 2px 선 → 4px, 4px 선 → 5px). 그래서 기본값을 3px에서 4px로 바꿨습니다.
2. 굵은 선의 두 경계는 양 끝에서 이어져 닫힌 획 하나가 됩니다. 처음 구현은 "다른 획끼리"만 비교해서 이 경우를 놓쳤습니다. 획을 따라가며 조금 뒤(lag = 3×dist+2px)의 점부터 그린 영역으로 표시하도록 바꿔, 한 획이 스스로 되돌아와 겹치는 경우도 잡습니다.

**이어붙이는 거리 조정.** 중복을 잘라내면 조각 끝에 틈이 생깁니다. 그래서 이어붙이는 거리를 2px에서 4px(펜 굵기 수준)로 넓혔습니다. 일러스트 1 기준, 중복 제거 후:

| 이어붙이는 거리 | 획 | 펜을 대고 긋는 길이 |
|---|---|---|
| 2px | 371 | 2804mm |
| 3px | 321 | 2824mm |
| **4px** | **273** | **2851mm** |
| 5px | 239 | 2883mm |

**최종 기본값(중복 제거 4px + 이어붙이기 4px) 효과.** 기존 값은 둘 다 끈 상태입니다.

| 이미지 | 획 | 펜을 대고 긋는 길이 |
|---|---|---|
| 일러스트 1 | 709 → 291 | 3735 → 2782mm (−26%) |
| 일러스트 2 | 429 → 250 | 2099 → 1734mm (−17%) |
| 만화 | 320 → 162 | 2985 → 3026mm (만화 선이 굵어 중복 제거 효과는 작음) |
| 사진 2 | 952 → 337 | 2253 → 1670mm (−26%) |

**검증 (단위 테스트).**
- 3px 떨어진 평행선 두 개 → 한 줄
- 20px 떨어진 별개의 선 → 둘 다 유지
- 기본 파이프라인에서 2px 굵은 선을 한 번만 그림 (끄면 두 번 그림)

## 3. 시간 추정 개선

**정의.**
- CLI와 GUI는 "펜을 대고 긋는 길이 ÷ 속도 + 이동 거리 ÷ 속도"만 계산했습니다.
- 실행기는 따로 계산했는데, 펜 올림·내림은 포함했지만 명령 지연은 빠져 있었습니다.
- 획마다 펜을 2.5mm씩 올리고 내리는 데 200mm/min 속도로 1.5초가 걸립니다. 명령마다 ok 응답을 기다리는 지연도 있습니다.

**해결.**
- `draw_executor.estimate_time()` 하나로 통일하고, CLI·GUI·실행기가 모두 이 함수를 씁니다.
- 결과를 항목별로 나눕니다: 그리기, 이동, 펜 올림·내림, 명령 수 × 명령 지연.
- 명령 지연은 `drawing_config.json`의 `timing.assumed_command_latency_s = 0.1`초로 둡니다. **가정값**이며, 실물 실행 기록(`LOG/runs`)의 `elapsed_s`와 비교해 보정해야 합니다.

**영향 (만화 기준).** 예전에는 "이론상 최소 11분"으로 나왔습니다. 새 추정은 약 21.5분입니다(그리기 10.1 + 이동 1.2 + 펜 올림·내림 4.2 + 명령 지연 6.0분, 명령 3629개). 명령 수는 단순화 오차(epsilon)에 크게 좌우되므로, GUI 슬라이더 설명에도 "클수록 명령 수 감소"라고 적었습니다.

**검증 (단위 테스트).**
- 명령 수가 `Planner.plan()` 결과와 같음
- 같은 길이를 10획으로 나누면 펜 올림·내림 시간만 9획분 늘어남

## 4. GUI 보강 (`CV/gui_sketch.py` 재작성)

- **이미지 종류 프리셋**(실사 사진 / 컬러 일러스트 / 흑백 만화): 상세도, rembg, 미디언 블러를 한 번에 설정합니다. 값은 `CV/presets.py`에 두고 CLI(`--type`)와 함께 씁니다.
- **세부 조절 탭:** Canny 임계값, 최소 선 덩어리, 단순화 오차, 미디언 블러, 이중선 제거 거리, 이어붙이기 거리, 선 후보 종류
- **A4 종이 미리보기:** 실제 비율로 그리고, 펜 굵기(`pen.line_width_mm = 0.5`, 추정값)를 반영합니다. 실행기 허용 범위(±50mm)는 파란 점선, 실물 미확인 범위(±60mm)는 주황 점선으로 표시합니다. 범위를 넘으면 상태 줄에 경고가 뜹니다.
- **예상 시간:** 항목별로 나눠 표시합니다.
- **로봇 시뮬레이션 버튼:** 관절 한계 PASS/WARN/FAIL과 최소 여유를 색으로 표시합니다. 끝나면 RViz용 관절 궤적을 저장할 수 있습니다.
- **rembg 캐시:** 원본 파일 해시 이름으로 `out/cache/`에 저장해, 두 번째부터는 기다리지 않습니다(`remove_background(cache_dir=...)`, CLI도 같이 사용).
- **한글 글꼴:** 맑은 고딕을 지정해 그래프 제목이 깨지지 않게 했습니다.

**검증.** 실제 Tk 창을 띄우고 만화 이미지로 확인했습니다.

## 앱 아이콘과 UI 디자인

사용자가 앱 이미지를 요청하고, UI를 더 예쁘게 만드는 방법을 물었습니다.

### 앱 아이콘 (`assets/make_icon.py`)

외부 이미지 없이 PIL로 직접 그립니다. 4배 크기로 그린 뒤 줄여서 가장자리를 매끄럽게 했습니다.
- **첫 시안:** 구도가 한쪽으로 쏠리고, 종이 위 낙서가 무엇인지 알아보기 어려웠습니다.
- **수정:** 종이를 가운데로 옮기고, 이 프로젝트에서 처음 그린 도형인 하트를 "그리는 중"으로 표현했습니다. 16~32px에서도 알아볼 수 있습니다.
- **선 이음새:** 점이 많은 곡선을 굵게 그리면 꺾이는 곳마다 가시 같은 자국이 생겼습니다. 꼭짓점마다 둥근 점을 찍어 해결했습니다.
- **출력:** `app_icon.png`(1024px), `app_icon_256.png`, `app_icon.ico`(16~256px). GUI 창·작업표시줄 아이콘과 README에 사용합니다.

### UI 방식 선택

| 선택지 | 판단 |
|---|---|
| sv-ttk | 2줄로 적용되지만 테마만 바뀜 |
| **CustomTkinter** | 사용자 선택. 처리 로직은 그대로 두고 화면만 교체할 수 있음 |
| PySide6 | 전체 재작성이 필요함 |
| Gradio | 웹 UI라 로봇 실행과 분리됨 |

### GUI 재작성 (CustomTkinter)

- **머리글:** 로고, 제목, 라이트/다크 전환. 미리보기 그림 배경색도 테마를 따라갑니다.
- **왼쪽 카드:** ① 이미지(종류 세그먼트 버튼) → ② 상세도와 크기 → ③ 실행(진행 바, 상태) → 세부 조절
- **오른쪽:** 미리보기 카드와 요약 카드 4개(획/명령, 그림 크기, 예상 시간, 시뮬레이션). 범위 초과는 주황·빨강, PASS는 초록으로 표시합니다.

### 발견한 버그: 작업 스레드에서 Tk를 직접 호출

**증상.** 테스트 중 "처리 실행" 뒤 90초가 지나도 결과가 오지 않은 적이 있었습니다. 또 다른 실행에서는 화면 캡처에 기대한 만화 대신 일러스트 1이 찍혔습니다. 이 두 번째 현상의 원인이 스레드 문제인지, 캡처 과정의 문제인지는 확정하지 못했습니다. 수정 후에는 재현되지 않았습니다.

**원인.** 작업 스레드가 `root.after()`나 위젯 설정을 직접 호출하고 있었습니다. Tkinter는 스레드에 안전하지 않아서, 이렇게 하면 멈추거나 순서가 꼬일 수 있습니다.

**해결.** 작업 스레드는 큐에 할 일만 넣고, 메인 스레드가 50ms마다 꺼내 실행하도록 바꿨습니다(`_ui()`, `_poll_ui_queue()`).

**검증.** 수정 후 같은 만화 이미지로 확인했습니다.
- 6.0초 만에 결과가 나오고, 경로·크기·획 수(166)가 맞음
- 상태 문구가 정상적으로 바뀜
- 시뮬레이션: PASS, 여유 12.4°
- 라이트/다크 캡처 모두 정상

진행 바가 반쯤 찬 채 멈춰 있던 문제는, 작업이 끝나면 확정 모드로 되돌리고 0으로 설정해 고쳤습니다.
