# 단계별 선 추출 파이프라인과 편집 제안(초록/빨강·번호)

설계 문서 · 2026-09-26 · 하위 프로젝트 1 / 4

## 1. 배경과 목표

지금의 선 추출은 `run_pipeline()`이 몇 개 안 되는 파라미터로 이미지 전체를 한 번에 처리한다. 결과를 다듬는 수단은 획 삭제·영역 삭제·되돌리기뿐이다. 그래서 다음이 어렵다.

- 어느 단계 때문에 선이 빠지거나 지저분해졌는지 알 수 없음 (중간 결과가 보이지 않음)
- 밝기가 비슷한 두 색의 경계가 흑백 변환에서 사라짐 (예: 주황 배경과 머리카락)
- 파이프라인이 버린 선을 되살릴 방법이 없음
- 사람이 "이 선"이라고 가리킬 번호가 없음

리터칭 기능은 네 개의 하위 프로젝트로 나눈다. 이 문서는 **1번**이다.

| 순서 | 하위 프로젝트 | 상태 |
|---|---|---|
| 1 | 단계별 파이프라인 + 미리보기 + 에이전트 편집 제안 | **이 문서** |
| 2 | 선 레이어 (외곽선 / 내부 디테일 / 명암 해칭) | 이후 |
| 3 | 영역별 설정 (얼굴은 섬세하게, 배경은 단순하게) | 이후 |
| 4 | 획 단위 손 편집 (마우스로 점 끌기, 올가미 등) | 이후 |

### 사용자가 정한 것

- 코드 구조는 A안(단계 객체 + 캐시 파이프라인)으로 한다.
- 선 검출에 색 차이(Lab) 방식을 추가한다.
- 화면은 단계 띠 + 큰 보기로 구성한다.
- 값을 바꾸면 자동으로 다시 계산한다.
- LLM 에이전트가 결과를 보고 선을 살리거나 지우고, 점을 편집할 수 있다.
- 살릴 선은 초록, 지울 선은 빨강으로 표시하고, 번호를 붙여 사람이 번호로 지시할 수 있게 한다.

### 가정 (사용자 확인 완료)

- **"살릴 선":** 파이프라인이 버린 조각(작은 덩어리, 잔가지, 겹침 제거로 빠진 부분)과 삭제한 획을 말한다.
- **제안 후 적용:** 초록·빨강은 적용 전의 **제안**이다. 사람이 확인하면 적용한다. 사람이 "바로 해"라고 하면 에이전트가 바로 적용할 수 있다.
- **범위:** 이번에는 마우스 손 편집을 하지 않는다. 편집은 에이전트 도구와 채팅의 번호 지시로 한다.

### 성공 기준

- 샘플 6장에서 리팩터링 전후의 `run_pipeline()` 결과(획 수, 총 길이, 좌표 해시)가 같다.
- 속도:
  - 뒤 단계 값만 바꾸면 0.3초 이하에 결과가 갱신된다.
  - 전체를 다시 계산해도 2.5초 이하다(rembg 제외).
- 밝기는 같고 색만 다른 경계를 Lab 방식이 검출한다.
- 설정을 바꿔 다시 계산해도, 적용된 지우기·살리기·점 편집이 유지된다.
- 에이전트가 제안한 편집이 화면에 초록/빨강과 번호로 보인다. "N번 빼고 적용"이 그대로 동작한다.

## 2. 단계 정의

| # | 단계 id | 이름 | 조절 항목 (키: 범위, 기본값) | 미리보기 | 버리는 것 |
|---|---|---|---|---|---|
| 0 | `source` | 원본 | `rembg`: bool, false | 컬러 원본 | — |
| 1 | `prep` | 전처리 | `median_ksize`: 0–15, 0<br>`blur_ksize`: 1–15(홀수), 5 | 흑백(또는 Lab의 L) 결과 | — |
| 2 | `edges` | 선 검출 | `edge_mode`: `luma` \| `lab` \| `dark`<br>`canny_low`: 0–255<br>`canny_high`: 0–400 | 검출된 선(검정 선/흰 바탕) | — |
| 3 | `trace` | 뼈대·획 추적 | `min_length_px`: 1–100<br>`spur_px`: 0–20, 6 | 획별 색 표시 | 작은 덩어리, 잔가지 |
| 4 | `dedupe` | 겹친 선 제거 | `dedupe_px`: 0–8, 4 | 남은 획 + 빠진 조각(흐리게) | 겹쳐서 빠진 조각 |
| 5 | `merge` | 이어 붙이기 | `merge_join_px`: 0–8, 4 | 이어진 획 | — |
| 6 | `simplify` | 단순화 | `epsilon_px`: 0.5–5.0 | 단순화된 획 | — |
| 7 | `edit` | 편집 | (없음) | 편집 적용된 획 + 제안(초록/빨강) + 번호 | 지운 획 |
| 8 | `paper` | 순서·종이 배치 | `box_mm`: 30–(허용 범위) | 그리는 순서, A4 미리보기, 예상 시간 | — |

- **단계 정의 구조:** 각 단계는 `Stage(id, label, params: [ParamSpec], run(inputs, params) -> StageOutput, preview(output, opts) -> image)`이다.
  - `ParamSpec`은 키, 이름, 종류(int/float/bool/choice), 범위, 기본값, 설명을 가진다.
  - GUI의 조절 칸과 에이전트의 `get_state`·`set_params` 설명은 모두 이 정의에서 만든다.
- **프리셋:** 사진/일러스트/만화 × 상세도는 여러 단계의 값을 한꺼번에 채우는 사전으로 남긴다. 값은 지금과 같다.
- **호환:** 기존 `line_source`(`canny`/`dark`)는 `edge_mode`(`luma`/`dark`)로 변환해 받는다.
- **순서 정하기의 위치:** 편집 뒤(8단계)로 옮긴다. 살리거나 새로 그은 선도 그리는 순서에 들어가게 하기 위해서다.

### 색 차이(Lab) 선 검출

- BGR 원본을 Lab으로 바꾸고, L·a·b 각 채널을 블러한 뒤 채널마다 Canny를 적용해 OR로 합친다.
- a·b 채널은 값 범위가 좁으므로, 채널별로 표준편차에 맞춰 대비를 늘린 뒤 같은 임계값을 쓴다.
- 입력은 `session.color`(흑백과 같은 크기)다. rembg를 켰으면 배경 제거 결과의 알파를 흰 배경에 합성한 컬러 이미지를 쓴다. 이를 위해 rembg 캐시를 컬러로 저장하도록 바꾼다.

## 3. 데이터 흐름, 캐시, 번호

```
원본 → 전처리 → 선 검출 → 뼈대·획 → 겹침 제거 → 이어 붙이기 → 단순화
                              ↓ 버린 조각     ↓ 버린 조각
                          [살릴 선 후보]
단순화 결과 ─► 편집 적용 ─► 순서 정하기 ─► 종이 배치(mm)
```

- **캐시:** 단계 k의 키는 `hash(단계 k의 설정, 단계 k-1의 키)`다. 값이 바뀌면 키가 달라진 첫 단계부터 다시 계산한다. 단계 결과는 메모리에 한 벌만 둔다(이미지 한 장 기준 수십 MB 이하).
- **자동 재계산:**
  - GUI는 값을 바꾸고 0.3초 뒤 작업 스레드에서 계산한다.
  - 세션은 세대 번호를 올리고, 끝난 계산의 세대가 최신이 아니면 결과를 버린다.
  - 에이전트의 `set_params`는 계산이 끝날 때까지 기다렸다가 결과를 돌려준다.
- **번호:**
  - 단순화가 끝난 획에 1부터 번호를 준다. 살릴 선 후보는 그다음 번호부터 받는다. 에이전트가 새로 그은 선은 새 번호를 받는다.
  - 편집 중에는 번호를 다시 매기지 않는다. 지운 번호는 비워 둔다.
  - 파이프라인을 다시 계산하면 번호를 새로 매긴다. 화면에는 "번호가 바뀌었습니다"라고 알린다.

### 편집 기록 (모양 기반)

번호는 다시 계산하면 바뀐다. 그래서 편집을 **모양**으로 기록한다.

- **`removed`:** 지운 모양(px 폴리라인) 목록. 다시 계산한 획 중 1px 간격 점의 60% 이상이 지운 모양의 2px 안에 들면 다시 지운다.
- **`added`:** 추가한 모양 목록. 살린 후보, 점 편집·매끄럽게·자르기·잇기의 결과, 새로 그은 선이 여기에 들어간다. 다시 계산한 뒤에도 그대로 더한다.
- **점 편집·매끄럽게·자르기·잇기:** 원래 모양을 `removed`에, 결과를 `added`에 넣는다.
- **맞는 대상이 없는 편집:** 다시 계산한 결과에 해당 모양이 없는 `removed` 항목은 "적용되지 않은 편집 n건"으로 알린다.
- **되돌리기:** 편집 목록 단위로 되돌린다(지금의 `undo`와 같음).
- **좌표:** 내부는 px로 저장한다. 그림 크기(mm)를 바꿔도 편집이 유지된다. 에이전트와의 입출력은 종이 mm로 한다.

## 4. 제안 → 확인 → 적용

- 에이전트의 편집은 먼저 **제안 목록**에 쌓인다. 제안마다 대상 번호, 종류, 전 모양, 후 모양을 가진다.
- **딱지 번호:** 대상 획이나 후보의 번호를 그대로 쓴다. 같은 번호의 제안이 여러 개면 하나로 합친다.
- **색:**
  - 🟢 초록: 새로 생길 모양(살리기, 편집 후, 새 선)
  - 🔴 빨강: 사라질 모양(지우기, 편집 전)
- **처리 방법:**
  - "전부 적용"
  - "N번 빼고 적용" (`exclude`)
  - "N번만 적용" (`only`)
  - "취소"
- **바로 적용:** `propose_edits`의 `apply_now: true`로 한다. 시스템 프롬프트에 "사용자가 바로 하라고 했을 때만"이라고 적는다.
- **다시 계산할 때:** 적용 전 제안이 남아 있으면, 제안의 모양은 유지하고 번호만 새로 매긴다.

## 5. GUI

```
┌ 머리글: Mirobot Sketch · [이미지 열기] · 테마 · ✦ 에이전트 ─────────────────────────┐
├ 단계 띠: [원본]→[전처리]→[선검출]→[뼈대·획]→[겹침]→[잇기]→[단순화]→[편집]→[종이] ┤
├──────────────┬──────────────────────────────────────────┬──────────────┤
│ 종류·상세도   │        큰 보기 (선택한 단계)                │  에이전트     │
│ ▸ 선택한 단계 │        휠=확대, 끌기=이동, 더블클릭=맞춤      │  패널         │
│   조절 항목   │  [원본 겹치기 ▁▃▅] [번호] [버린 선 보기]      │              │
│ 시뮬레이션    │  제안 7건 🟢3 🔴4 [전부 적용] [취소]  #813 #5 … │              │
│ RViz·내보내기 │  획 812 · 90×110mm · 12.4분 · 시뮬 PASS    │              │
└──────────────┴──────────────────────────────────────────┴──────────────┘
```

- **단계 띠:** 썸네일(짧은 변 약 90px)을 보여 주고, 누르면 그 단계를 선택한다. 다시 계산할 단계는 흐리게 표시하고, 끝나면 갱신한다.
- **큰 보기:**
  - matplotlib 축에서 휠로 확대, 끌어서 이동, 더블클릭으로 맞춘다.
  - 획은 `LineCollection` 하나로 그린다.
  - **원본 겹치기:** 투명도 0–1로 조절한다.
  - **번호:** 확대된 범위 안에 보이는 획 중 화면상 길이 20px 이상인 것만 표시하고, 제안 딱지는 항상 표시한다.
  - **버린 선 보기:** 후보를 회색 점선과 번호로 표시한다.
- **제안 바:** 제안이 있을 때만 보인다. 딱지를 눌러 켜고 끄고, [전부 적용]은 켜진 딱지만 적용한다.
- **조절 칸:** `ParamSpec`에서 슬라이더, 선택지, 스위치, 숫자 입력 칸을 자동으로 만든다. 에이전트가 값을 바꾸면 따라 바뀐다.
- **요약 줄:** 획 수, 크기, 예상 시간, 시뮬레이션 결과를 보여 준다. 시뮬레이션, RViz, 내보내기 버튼은 지금 동작 그대로 둔다.
- **테마와 창 크기:** 라이트/다크 테마를 따른다. 창이 좁으면 큰 보기가 먼저 줄어든다.

## 6. 에이전트 도구

| 도구 | 입력 | 출력 |
|---|---|---|
| `get_state` | — | 단계별 현재 값·범위, 획·후보 수, 제안, 적용 안 된 편집, 예상 시간 |
| `set_params` | `{키: 값}` | 적용된 값(범위로 잘린 값), 다시 계산한 단계, 바뀐 수치 |
| `view` | `kind`: `original` \| 단계 id \| `edit` \| `paper`<br>`region_mm`, `numbered`, `show_candidates`, `overlay_original`(0–1) | 이미지(최대 1000px) + 설명 |
| `list_strokes` | `region_mm`, `include_candidates` | 표: 번호, 종류(획 / 후보+이유), 길이 mm, 테두리 상자, 점 수 |
| `get_stroke` | `id` | 점 좌표(mm, 점 번호), 최대 400점 |
| `propose_edits` | `ops[]`(최대 200), `apply_now` | 만든 제안 번호, 바뀌는 부위를 확대한 초록/빨강 미리보기 이미지 |
| `apply_proposals` | `exclude` 또는 `only` | 적용 결과, 새 획 수·예상 시간 |
| `discard_proposals` | `ids` 또는 전부 | — |
| `undo`, `simulate` | 지금과 같음 | 지금과 같음 |

**`ops`의 종류**

| op | 인자 |
|---|---|
| `delete` | `ids` |
| `restore` | `ids` (후보 번호) |
| `delete_region` | `region_mm`, `mode`(inside/crossing), `min_fraction` |
| `move_point` | `id`, `index`, `to_mm` |
| `delete_points` | `id`, `indices` |
| `insert_point` | `id`, `after_index`, `at_mm` |
| `smooth` | `id`, `strength`(1–5) |
| `split` | `id`, `index` |
| `join` | `a`, `b` (가까운 끝끼리 잇기) |
| `add_stroke` | `points_mm` (2–200점) |

- **정리되는 도구:** 기존 `delete_strokes`, `delete_region` 도구는 `propose_edits`로 합친다.
- **입력 검사:**
  - 번호, 점 번호, 종류를 검사한다.
  - 종이 허용 범위(`limits_pending_verification`) 밖의 좌표는 거부한다.
  - 잘못된 입력에는 예외 대신 오류 메시지를 돌려준다(`AgentToolbox.call`의 규칙 유지).
- **시스템 프롬프트에 적을 작업 흐름:**
  1. 원본을 겹친 `view(edit)`를 본다.
  2. 문제 부위를 확대하고 `list_strokes`로 번호를 확인한다.
  3. `propose_edits`로 제안하고, 미리보기로 스스로 검토한다.
  4. 사용자에게 번호로 설명하고 확인을 기다린다.

| `mirobot_sketch/gui.py` | 조절 칸 자동 생성, 자동 재계산 연결, 레이아웃 변경 |
| `mirobot_sketch/agent/tools.py` | 6장의 도구, 시스템 프롬프트 |

## 8. 테스트와 확인

- **리팩터링 전후 비교:**
  - 시작 전에 샘플 6장 × 프리셋의 결과를 `tests/data/pipeline_golden.json`에 저장한다(획 수, 총 길이, 좌표 해시).
  - 리팩터링 뒤 `run_pipeline()`과 `Pipeline` 모두 같은 결과가 나오는지 확인한다.
  - 샘플 이미지가 없는 CI에서는 합성 이미지 기준값을 쓴다.
- **단계와 캐시:**
  - 단계 정의가 올바른지(범위 안의 기본값, 키 중복 없음) 확인한다.
  - 뒤 단계 값만 바꾸면 앞 단계의 계산 횟수가 늘지 않는지 확인한다.
  - 오래된 세대의 결과가 버려지는지 확인한다.
- **Lab 검출:** 밝기는 같고 색만 다른 합성 이미지에서 `luma`는 경계를 거의 못 찾고, `lab`은 찾는지 확인한다.
- **후보:** 작은 덩어리, 잔가지, 겹침 조각이 이유와 함께 기록되는지, `restore` 후 획이 되는지 확인한다.
- **편집:**
  - op별 결과 모양을 확인한다.
  - `set_params`로 다시 계산해도 지운 선은 다시 지워지고, 추가한 선은 유지되는지 확인한다.
  - 적용되지 않은 편집이 보고되는지 확인한다.
  - 범위 밖 좌표 거부와 200개 제한을 확인한다.
- **제안:**
  - `exclude`, `only`, 취소, 되돌리기를 확인한다.
  - 렌더링 이미지에서 제안 위치의 픽셀이 초록·빨강인지 확인한다.
- **에이전트:** `AgentToolbox` 직접 호출 테스트와 MCP stdio 전체 경로 테스트를 한다(기존 방식).
- **GUI:**
  - 전체 모듈 컴파일 테스트를 한다.
  - 스크립트로 앱을 띄워 이미지 열기 → 값 변경 → 자동 재계산 → 제안 표시 흐름을 확인한다.
  - 라이트/다크 화면을 캡처해 직접 본다.
- **속도:** 샘플 6장으로 1장의 목표를 측정해 LOG에 기록한다.

## 9. 진행 순서

1. **1a:** 기준값 저장 → `stages.py`와 Pipeline·캐시 → Lab 검출 → 세션 연결 → 단계 띠·큰 보기·자동 재계산 GUI → `set_params`/`view` 도구 갱신 → LOG
2. **1b:** 후보 기록 → `edits.py`(편집·재적용) → 제안·렌더링 → 제안 바 GUI → 에이전트 도구 → LOG

1a만 끝나도 앱은 정상 동작한다(편집은 기존 삭제·되돌리기 수준).
